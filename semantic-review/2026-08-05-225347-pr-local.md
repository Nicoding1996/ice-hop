# Feed-safe Daily teaser and Community status preview

The change moves feed rendering off `/api/init`: Daily posts embed dimensions and piece counts, Community posts embed the exact submitted board, and `/api/post-preview` supplies legacy fallback plus live Community solve state without issuing a Daily play. Expanded mode then calls `/api/init`; Daily initialization issues a persistent server clock before returning exact cells, while Community completion remains untimed and transcript-verified. The spoiler boundary holds on the normal path, but post identity failures can select the wrong mode and the elapsed-time tiebreaker is not connection-neutral.

**Watch for:** **confirmed** — a missing Community post link or submission falls through to today’s Daily while the card can keep showing the embedded Community board; **confirmed** — Daily elapsed time includes response delivery, client rendering, completion upload, and retry delay after a lost init response.

## High-level view

**Confirmed:** post creation publishes `postData` before writing the Redis post-to-puzzle link. Both preview and init interpret “not resolved as UGC and not mapped as Daily” as “today’s Daily,” so mapping availability can change which puzzle opens instead of producing an unavailable state.

**Confirmed:** `issueDailyPlay` records the start before the init response leaves the server and reuses it for signed retries. The leaderboard therefore includes infrastructure, rendering, and recovery delay in addition to player solving time.

**Confirmed:** the position-free Daily card prevents accidental feed spoilers, but another guest/account can fetch the shared exact board without touching the ranked account’s per-user clock.

**Confirmed:** Play enters an `opening` state before invoking a void, synchronously-throwing SDK effect. It has no idempotency or recovery guard, and an in-flight preview can overwrite its progress label while leaving it busy.

**Likely:** static HTML always paints a generic hero until the external module reads postData. Cold module loading can therefore flash and reflow every new Daily card before the board teaser appears.

## P1 — Community post identity fails open to today’s Daily

**Confirmed.** `createUgcPost` publishes the Reddit post, including its exact board, before `keys.ugcPost(post.id)` is written (`src/server/core/post.ts:117-134`). A mapping-write failure leaves a live orphan; a missing `ugcSubmission` creates the same resolution state later. Both `/api/post-preview` and `/api/init` skip unresolved UGC and use `hostRef ?? getCanonicalDailyRef(todayUtc())` (`src/server/routes/api.ts:99-140`, `src/server/routes/api.ts:152-204`).

Once postData renders a Community board, `renderDailyStatic` refuses to replace it (`src/client/splash.ts:501-535`). A complete Daily teaser similarly skips preview resolution (`src/client/splash.ts:583-605`).

```text
Community postData: board A
        |
        +--> splash displays board A
        |
missing/stale Redis post link
        |
        +--> /api/post-preview resolves today’s Daily (ignored by splash)
        +--> /api/init resolves today’s Daily and starts its clock
```

A creator-credited Community card can therefore open an unrelated Daily, remove Upvote/Next/creator-credit behavior, and unexpectedly start the Daily timer. An orphaned Daily post likewise changes to the current Daily after rollover despite retaining its historical teaser/title. Host resolution should fail closed or derive from an immutable, server-verifiable identity carried by the post.

## P1 — Daily time ranks delivery and recovery latency as solving time

**Confirmed.** `issueDailyPlay` records `startedAt: Date.now()` and returns the existing play for later signed init calls (`src/server/core/completion.ts:130-151`). `/api/init` starts it in parallel with prior-solve and subscription reads before serializing the board (`src/server/routes/api.ts:192-218`). Interaction begins only after response receipt, JSON parsing, layout, and render (`src/client/scenes/GameScene.ts:452-505`); the stop time is sampled only when `/api/solve` reaches `getDailyElapsed` (`src/server/routes/api.ts:243-266`; `src/client/scenes/GameScene.ts:2353-2367`).

Both network legs, post-issuance server work, and client render time affect tie order. If init stores the issue but its response is lost, the 12-second client timeout and subsequent Try again still use the original start (`src/client/scenes/GameScene.ts:593-601`). Optimal-move ties can therefore be reordered by connection quality or an infrastructure failure. This needs an explicit delivery/ready or bounded-grace model, otherwise time should not decide competitive rank.

## P2 — A second identity can pre-study the shared Daily

**Confirmed.** `/api/init` returns the same host/canonical Daily board to guests and signed users (`src/server/routes/api.ts:152-218`). Guest capabilities are stateless, while signed play state is keyed by puzzle and username (`src/server/core/completion.ts:130-170`; `src/server/core/keys.ts:31-37`), so one identity’s disclosure does not start another identity’s clock.

A logged-out session or second account can solve the board first, then the ranked account can open it with a fresh start. The feed teaser protects only against accidental pre-study in the same flow; it cannot secure fastest-time ranking across identities. Move count remains server-verifiable, but time should be treated as non-competitive unless this limitation is explicitly accepted.

## P2 — Opening state is neither idempotent nor recoverable

**Confirmed.** Play sets `body.opening`, `aria-busy`, and “Opening puzzle…” before calling `requestExpandedMode`, but never disables the button, catches a synchronous SDK exception, or restores state (`src/client/splash.ts:13-27`). The installed SDK returns `void` and can throw, so failure leaves a busy card and repeated taps can emit repeated expansion effects.

Community and legacy cards can also have `loadPostPreview` in flight when tapped. `applyUgcStatus` and `renderDailyStatic` overwrite the button label unconditionally (`src/client/splash.ts:521-558`, `src/client/splash.ts:562-605`), allowing normal Play copy to reappear while `aria-busy=true` and the opening animation remain. Guard the transition once, keep status rendering from mutating transition UI, and reset on synchronous failure or inline focus return.

## P3 — Daily postData does not control literal first paint

**Likely.** `splash.html` contains the generic penguin hero and default Daily copy; only the external deferred module reads postData and replaces the hero (`src/client/splash.html:27-92`; `src/client/splash.ts:532-549`, `src/client/splash.ts:583-605`). With a cold/throttled module, the browser can paint that hero before swapping to a larger board and the compact `body.puzzle-preview` layout (`src/client/splash.css:262-306`).

The path avoids a server round-trip but can still flash and shift. Static HTML should reserve the final preview geometry or use a matching board skeleton so module execution changes content without reflowing the card.
